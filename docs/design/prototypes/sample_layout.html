Polling Distributed State Instead of Sleeping

A DNSSEC migration investigation showing why observable distributed state is more useful than blindly waiting fixed provider timelines.

Atlas context: Infrastructure → DNSSEC. Related domains: Distributed Systems, Observability.

The operational problem

Provider documentation suggested waiting 24–48 hours after disabling DNSSEC before continuing a domain migration. Direct DNSSEC inspection showed that relevant trust-chain state could be observed rather than guessed.

Why DNSSEC behaves like distributed state

The parent zone, authoritative nameservers, and recursive resolvers can temporarily disagree because they cache, refresh, and validate records independently. 

dig DS mroux.net @1.1.1.1
dig DS mroux.net @8.8.8.8

The broader engineering lesson

In infrastructure workflows, polling observable state is often superior to fixed sleep timers. This pattern generalizes to deployments, failovers, stream processors, and cache invalidation workflows.
